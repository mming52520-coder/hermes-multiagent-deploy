# 工作台使用说明

## 项目架构师对话

支持的新后端在「工作流」页显示每个项目及看板唯一的一条架构师对话。可以连续讨论并生成多个任务，无需切换会话或分别找执行角色。原生「对话」页仍是 Hermes 终端入口。

| 操作 | 行为 |
|---|---|
| 发送消息 | 讨论需求、架构和风险；文字「可以」「接受」不改变任何任务状态 |
| 生成任务卡 | 将可编辑草案建立为未审批任务；后台角色尚未启动 |
| 卡片「批准并开始」 | 在确认窗口核对完整需求和轮次，再批准后台执行 |
| 确认验收／提出修改／不做了 | 在对应卡片上明确选择；修改或不做须填写原因 |
| N 项待你决定 | 定位最早一张未处理卡片 |
| 任务 | 打开或收起右侧抽屉，查看任务列表、阶段图、工作过程和证据 |
| 历史对话（只读） | 查看升级前的对话，原消息保留；后续讨论使用项目架构师会话 |

首次讨论时会把当前项目与看板已有的 v2 任务关联进同一时间线，旧会话不会被改写。历史 v1 任务继续在任务抽屉按原确认方式处理。

系统进展用灰色条目展示，不冒充架构师发言。模型生成的推荐标注「架构师建议」；没有模型、调用失败或超时时显示规则说明。推荐按轮次及状态缓存，刷新页面不会重复请求同一推荐。建议本身没有审批能力，后台质量校验、预算及授权规则继续生效。

决策完成后，卡片保留在原位置，显示操作者、时间、渠道、结论及填写的原因。过期卡片不能再次执行；页面遇到冲突会刷新。飞书通知中的 `?card=<id>&execution=<id>` 优先定位决策卡；只有 `?execution=<id>` 时打开对应任务抽屉。

架构师使用 Hermes 主模型；首次使用先在本机「模型」页面配置连接。四个执行角色仍通过「模型配置」管理。密钥在本机密钥表单输入，不要发到对话中。飞书双向处理属于下一阶段，本次仍使用已有 Webhook 发送通知与网页跳转。

## 兼容工作台

以下保留未启用架构师布局时的操作说明。

客户主界面显示任务、总控对话、进度和结果。模型配置默认收起；完整需求、版本、验证日志与整改记录放在「详细记录」。界面保留中英文切换。

## 开发一个新任务（流程 v2）

1. 点击「新建任务」，在总控对话中描述需求。总控使用主模型回复，可继续讨论或修改生成的草案。
2. 点击「生成任务卡」，核对需求后点击「批准并开始」。讨论和生成任务卡不会启动执行角色；总控回复会使用模型 API。
3. 系统自动完成方案、开发、独立测试和审查。「工作过程」持续更新各角色的公开工作摘要、工具调用与结果，可按角色筛选。开发与独立测试设计并行，测试在冻结候选上执行。
4. 通过后查看代码改动或下载交付代码，点击「确认验收」。待验收时也可「提出修改」，批准新的修改轮次；失败时填写整改意见并点击「批准整改并执行」。

审批后的推进由原生 Gateway 执行，不需要保持浏览器打开。首轮执行和每次整改均需授权，最终交付也需确认。运行中与总控讨论的新想法不会改写已批准任务。环境尚未就绪时修复配置后点击「继续执行」；角色运行中断时，可保留失败记录并明确重试该角色。

选择已有任务会恢复与它绑定的总控对话；发送进展问题时会附带最新真实状态。对话保存到原生会话库，刷新页面后仍可继续。服务重启中断的回复会明确提示重新发送。实时过程展示公开产出和调用记录，不展示模型内部逐字推理。原生侧栏「对话」保留原终端界面；总控入口在「工作流」工作台。

点击方案、开发、独立测试、独立审查可查看各阶段真实报告、测试记录及实际使用的技能。测试设计完成不代表最终测试通过；冻结版本的平台测试通过后才进入独立审查。任务标题使用需求首行，全文保留在详细记录和操作确认窗口中。

旧版任务保留原有「确认需求 → 开始开发 → 开始审查 → 检查并交付」流程，以及调查、开发、独立审查、最终汇总的历史记录。

## 常用入口

| 入口 | 作用 |
|---|---|
| 模型配置 | 在同页配置四个角色的厂商、Key 与模型；可各自配置或共用连接 |
| 新建任务 | 开始与总控讨论一个新需求 |
| 总控对话 | 讨论需求、修改草案或询问所选任务进展 |
| 生成任务卡 | 将草案保存为待审批任务 |
| 工作过程 | 按角色查看实时工作摘要、工具调用与结果 |
| 查看代码改动 / 下载交付代码 | 查看与下载冻结的交付版本 |
| 当前步骤卡片 | 写明现在要你做什么和原因；主按钮按状态为批准并开始、批准修复、继续执行、重试失败角色或确认验收，「提出修改」和「不做了」在同一行 |
| 不做了 | 红色按钮。填写原因后确认，原话写入「定了不做的事」；有角色运行时不可用 |
| 收起对话 | 窗口宽度 1280px 以下时出现，收起中间的总控对话，对话仍在后台更新 |
| 阶段卡片 | 查看对应阶段结果、实际技能与测试记录 |
| 详细记录 | 查看需求全文、执行准备、版本、验证记录及整改记录 |
| 批准整改并执行 | 查看问题并填写修改意见，授权新一轮开发和测试；失败分类保留在「更多选项」中 |
| 重新读取 | 读取失败时重试；正常情况下每 20 秒自动更新 |
| 取消 | 关闭未确认的操作窗口 |

模型配置收起后会保留当前未保存的输入。保存成功后返回任务界面。同步到未启动任务时，后台会撤销旧审批并要求重新确认。新任务使用方案、开发、独立测试、独立审查四个独立连接；新增的测试角色可沿用原第四角色已保存的连接，原最终汇总连接和历史任务配置继续保留。

## 状态与颜色

任务列表把需要你处理的任务排在最前，标题旁显示「N 项待你处理」。打开页面时默认选中第一个需要你处理的任务。状态颜色在列表、详情标题和阶段卡片中一致：

| 颜色 | 含义 |
|---|---|
| 琥珀 | 需要你：待审批、待验收、待修复、需要处理、已阻塞 |
| 蓝 | 正在执行或等待依赖 |
| 绿 | 已完成或已验收 |
| 灰 | 已决定不做、已归档 |

当前步骤卡片会说明原因：审查发现几个阻断问题、即将开始第几轮，整改轮次用完时不再提供修复，只能手动处理或决定不做；角色中断或阻塞时写明是哪个角色；已决定不做的任务显示原话和日期。阶段流程按「方案 → 开发 ∥ 独立测试 → 独立审查」显示，开发与独立测试上下并列。「工作过程」以时间线显示，工作摘要和阶段结果直接展开，工具调用默认折叠为一行。

## 键盘

Tab / Shift + Tab 移动焦点；Enter / 空格操作按钮；总控输入框 Enter 发送、Shift + Enter 换行；Esc 关闭尚未执行的确认窗口。新界面通过明确的「批准并开始」或「确认验收」按钮授权，旧版任务保留原确认方式。处理中不能重复提交。

## 验收与记录

新任务在平台完整测试和独立审查通过后显示待确认交付。平台测试记录绑定代码内容、版本、实际镜像、命令和独立测试集；相同输入复用有效证据，变更输入后重新执行。审查失败直接进入整改，不启动无效汇总。等待人工审批的时间与实际执行时长分开记录，费用未采集时显示未知。

技术记录按需展开，正常页面不显示 Profile、源版本号、内部编号、调试指标、说明段落或安全验证横幅。用户需求、模型结果、命令及原始日志保留原文。
