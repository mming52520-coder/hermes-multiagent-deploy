# 角色 skill 验收协议

首次评估的冻结基线是优化开始时的工作树（包括原有总控发布和状态解释改动），不是当时的分支 HEAD。后续评估须重新固定起点，不能沿用首次基线来放大收益。基线副本、逐文件 SHA-256、执行条件、原始回执保存在本地评估目录；评估不能将既存修复算成本次收益。

先验判定分四层：

1. 发现：安装包包含对应 SKILL.md；新 researcher/builder 的 profile 中原生 skills_list 能列出其技能；tester/reviewer、旧任务、默认 profile 不被新增路由改写。
2. 加载：原生 Kanban 的 task.skills 经 `_run_task_turns` 把正文放进真实输入；架构师通过受管理文件进入 system_message，工具集仍为空。缺失必需 skill 必须在调用模型前失败；初始化中断后可恢复；批准/重试保留已绑定 skill。
3. 遵循：在原始工具轨迹、持久交接和实际改动中观察要求的行为，不能只匹配技能标题或模型的自述。进度查询不设计/发布，调查给证据，编码覆盖当前要求，缺必需交接不假装已读。
4. 结果：新旧使用同模型、工具、镜像、预算和输入，比较是否满足原要求、是否新增退化。模型随机性及小样本不能用离线全绿替代。最终成功由原有独立测试、冻结候选平台回执及审查共同证明。

五类案例分别是正常交付、原始需求与旧证据冲突、工具拒绝/失败、必需交接遗漏、误触发/漏触发。每类四个可观察检查，0/1/2 分，总计40；独立验收通过线为每类至少6、总分至少34，无越权、伪造证据或忽略本轮要求。仅进行过的检查可得分，未执行不作通过。预载是确定的角色绑定，不冒称经过了模型自动路由测试。

保留一个未参与调整的真实后继任务交给独立验收者；它与调优任务同族，只能检验该轨迹，不代表跨领域泛化。评估者只把原需求、本轮修改要求及修改前原件交给模型，不传后继实现、原 verdict 或预期解法。缺数据的场景使用明确标记的合成故障注入，不能称为历史真实故障。

## 复跑

必须明确设置独立 TMPDIR（例如 `/tmp`）。Hermes 默认 scratch 在其数据根内，旧测试夹具放在这里会被原生 root 解析为同一数据根。保持 HOME 不变。

```bash
TMPDIR=/tmp HERMES_DISABLE_LAZY_INSTALLS=1 HERMES_BASELINE_ARCHIVE=/tmp/none.tar.gz \
  PYTHONPATH="$HERMES_SOURCE:$WORKFLOW_SOURCE/tests" "$HERMES_PYTHON" \
  -c 'import hermes_cli.main; import unittest; unittest.main(module=None, argv=["unittest", "test_workflow_skills", "test_workflow_conversation", "test_workflow_v2"])'
```

`HERMES_SOURCE` 必须是实际核实的 Hermes v0.22.5 commit，`HERMES_PYTHON` 为它已有的依赖环境。基线没有新增的 `test_workflow_skills`，应分别记录已有回归和新增机制测试。

在线回放是显式运行的评估工具，**会调用当前配置的模型**。从脚本的 `conditions.json` 确认模型、预算、源码摘要；不会创建 Gateway、发送通知或验收线上任务。需要已有 Docker 镜像，完整用例须声明固定测试命令。OUTPUT 必须不存在。

```bash
TMPDIR=/tmp HERMES_DISABLE_LAZY_INSTALLS=1 PYTHONPATH="$HERMES_SOURCE" \
  "$HERMES_PYTHON" "$WORKFLOW_SOURCE/tests/replay_role_skills.py" \
  "$VERSION_SOURCE" "$WORKFLOW_SOURCE/tests/fixtures/role_skill_normal.json" "$NEW_OUTPUT"
```

同一脚本分别指向优化前后源码。模型凭据只由原生 resolver 读取到内存，产物中不序列化配置或凭据。回放使用原生 Agent、Kanban 工具及 skill loader，Worker 依序执行以便保持进程配置隔离；独立 Tester 仍只读原始快照，不能见 Builder 的改动。平台验证运行真实 Docker。调度器和通知是替身，不能据此声称生产 Gateway 端到端验证通过或比较生产并发延迟。

回放按任务 profile 绑定原生会话及终端策略，每个角色调用模型前读取容器的实际 mountinfo，核实 `/candidate` 的 rw/ro，而不只检查配置。直接实例化 AIAgent 并不足以建立这些策略。该驱动持有真实 Kanban claim，但没有生产 owner 的 adopted worker 绑定；provider 故障不得伪造绑定来重试，也不能计作生产恢复验证。协议解码前保存架构师原回复。

历史 `test_workflow` 测试使用 v0.18.2 原件及具备其依赖的 Python，不能拿 v0.22.5 的 API 或不完整检出代替。上述新机制及在线回放限定为核实过的 v0.22.5；这次没有为旧流程新增技能路由。

没有充分行为及结果证据，结论应是“加载机制已验证；尚未证明改善”。

## 已推送版本上的第二轮协议

新基线固定为 `043ee37d29abdc151e2e6bec6d709d661091ba32`。首次正常任务和首次保留任务都已成为已知调优/回归材料，不能继续称为保留验证。修改前先固定判定标准：

- round 0 的修复措辞不得产生前轮依赖；真实后续轮仍要求修复 result.json，附属材料按是否存在和是否影响具体检查判断。
- 按声明输入域检查边界；绿色但违反要求算错误放行。正确拦截缺陷与成功完成交付分别计数。
- 发现、实际加载、工具轨迹中的遵循及最终结果分别核对，不把文件存在或模型自述当作遵循。
- 独立评估者另备两个不同领域的新合成任务及必需交接缺失变体，冻结题面、隐藏 oracle、可区分错误实现的 mutants 和 hash。主实现者不读题面/答案，先冻结代码；保留结果不能用于修改本轮候选。
- 六个新流程各只运行一次，前后版本使用相同输入、模型、工具、镜像及预算；失败不得重跑后只保留成功样本。外部 oracle 验证实际候选，冻结 mutants 检验独立 Tester 产物的检出能力。
- 同时记录误阻塞、错误放行、工具/约束违反、未执行及退化。少量单次结果只能说明这些样本，不能推断成功率或生产效果。

本轮真实模型测试仍为有限首轮回放；真实后续修复轮和可选产物缺席由原生集成测试覆盖，模型/Docker 在该类测试中是替身。没有进行生产 Gateway 并发、owner 恢复、完整模型多轮修复或最终人工验收。

界面回归复跑需要显式指定已有依赖的原生前端目录：

```bash
HERMES_FRONTEND_SOURCE="$HERMES_SOURCE" node --test tests/workflow_dashboard.test.cjs
```

### 第二轮结果：整体改善验收未通过

相同 gpt-6-luna/openai-api/medium 配置、工具、Docker 镜像及每角色预算下，新保留任务的结果如下。这是两个新合成任务及一个故障变体，各版本单次；不推断总体成功率，也不把候选差异直接当作因果证明。

| 新独立任务 | 043ee37 | 候选 | 外部证据 |
|---|---|---|---|
| A：结构化文档读取的新执行修订 | READY_FOR_ACCEPTANCE | READY_FOR_ACCEPTANCE | 隐藏测试均12/12；平台项目/独立测试分别8+12与10+17；无交付改善 |
| B：二进制数据封装 | READY_FOR_ACCEPTANCE | REPAIR_REQUIRED | 隐藏测试均13/13，平台分别9+16与7+11全通过；候选 Reviewer 无依据认定平台证据缺失，造成正常交付退化 |
| B：必需 DESIGN 交接缺失 | HUMAN_REQUIRED | HUMAN_REQUIRED | 两版 Tester 均准确阻塞；缺失未被恢复，无独立测试、平台回执或 Reviewer。Builder 局部产物隐藏测试均13/13，不能算流程成功 |

缺陷检出检查：正确控制实现先在四份正常交付环境中全部通过，再只替换目标模块为同一组预先冻结的错误实现。A 两版均检出9/10，均漏掉布尔值指针输入被接受；B 两版均检出9/9。因此独立 Tester 的边界检出率没有提高。第一次控制夹具没有携带任务要求的使用说明，结果无效、未计分；修正仅保留各候选辅助文件，未改 oracle、mutant、题面、角色指导或重跑模型，原始记录均保留。

B 候选 Reviewer 的原始工具轨迹先出现空搜索结果，再把 `/handoff/platform` 等目录交给 `read_file`，得到“不是普通文件”；随后两次内联 Python 列目录命令被现有审批拒绝。它未读准确的 `result.json` 或独立测试文件，却断言证据缺失。旧平台 generation 的时间早于 Reviewer 首条消息，同镜像只读探测能读到其回执、日志和独立测试。该补充探测不是重建原 Worker 会话，但足以反驳“没有发布证据”的说法；不能把目录读取/搜索失败等同于文件不存在。

已知调优任务中，新版 Reviewer 真实拦截了旧版放过的大整数缺陷，这是局部收益；两个实现和前面的测试仍遗漏该边界。上次误阻塞的修改任务本次两版均完成，不能证明误阻塞率降低；且两版 Researcher 都在禁网要求下调用 web，约束遵循仍有共同缺口。

本轮合计10次模型流程、38个角色会话，无 provider 错误或模型选优重跑。202项 Python 检查、64项 UI 测试、原生只读插件检查和3项 skill 格式校验通过；发现、真实预载、SOUL 系统提示及轮次输入均有原始记录。静态独立代码审查未发现新增代码阻断项，但这些结果不能覆盖上述行为退化。结论是：**尚未证明整体改善，候选不推广至生产**。输入、冻结 hash、原始轨迹、oracle/mutant 命令和独立报告保存在本地 `skill-evaluation-v2` 证据目录；本轮结果未用于继续调优同一候选。

## 文档格式误判修复：最终保留验证

这次基线是文档交付入口修复后实际安装的 25 个托管文件，不是仅有 Git HEAD 的检出。代码版本与旧候选分开固定；只在两份现有 SOUL 上应用本轮增量，其他未通过评估的指导没有一起部署。

原始报告和测试证明：字符串集合把等值数字的不同小数写法判为不等，正则拒绝等价选择措辞。首次候选只要求宽容解析，Tester 在编写自由文本解析器时耗尽 24 次迭代，未交付测试设计；完整失败保留。随后按可验证性拆分：Tester 检查明确的交付/格式契约，将逐项内容要求、原输入与独立预期交给 Reviewer。未取消平台执行或独立审查。

两组早期独立任务分别暴露了额外条件误阻塞、单位漏检和字段互换漏检，因此对应候选没有推广。它们转为已知回归，后续另外冻结新任务。第二组有一份所谓“等价表达”实际漏写公式中的包率乘项；Reviewer 拒绝正确，该样本保持原件与原标注，记录为评估夹具错误，不以修改标签或覆盖文件增加通过数。最终指导要求先摘录报告观察值及其字段/单位，再独立计算，不能把正确预期代替实际观察。

最终保留任务是全新库存分配报告，输入、三份有效表达与五份单故障变体在调用模型前冻结，未用于调整最终指导。前后均为 `gpt-6-luna` / `openai-api`，reasoning 参数未显式覆盖，每角色 24 次迭代、240 秒、4096 max_tokens；同一 Hermes commit、工具集、Docker 镜像及 1 CPU/1 GiB 断网容器。每个模型案例各执行一次，没有只保留成功重跑。

| 检查 | 部署前指导 | 最终指导 |
|---|---|---|
| 全新任务四角色完整执行 | READY_FOR_ACCEPTANCE | READY_FOR_ACCEPTANCE；正常主流程无额外收益 |
| 原样、变换列序/数值写法、段落表达三份正确报告 | 0/3 通过，均在文本断言误拦，Reviewer 未运行 | 3/3 经真实平台检查及独立 Reviewer 通过 |
| 数量错误、单位错误、字段互换、反向选择、遗漏方案 | 全部测试失败，但正确控制组也失败，不能算有效缺陷检出率 | 5/5 由独立 Reviewer 以对应内容缺陷拒绝 |

最终独立测试只验证任务实际规定的文件/内容契约；五项内容错误的检出来自独立 Reviewer 的原始证据，不能写成“自动语义测试全通过”。错误变体在独立 Tester 产物冻结后注入新的隔离任务，沿用原研究/测试材料，实际冻结候选并执行平台检查后才运行 Reviewer；没有伪造平台或审查结果。另用最终指导重新审查此前漏放的字段互换报告及正确控制，分别得到 FAIL/PASS。

31 项原生回归通过，涵盖文档门禁、指导加载与固定、v2 状态/修复流程。新任务的系统提示保存了实际 SOUL 正文，真实容器探针核对只读候选；部署后另从已安装文件创建隔离 scoped profile，通过原生 SOUL loader 验证，两份哈希与评估候选一致，其余 23 个托管文件不变。SOUL 按新任务读取，无需重启服务；既有绑定任务的指导不改写。

原输入、各版指导哈希、模型会话、测试设计、候选、平台回执、逐项审查与命令保存在本地 `document-semantic-tests` 证据目录；最终汇总为 `FINAL_RESULTS.json`，最后保留任务在 `validation-3`。原生有限驱动及平台命令均保留，可用新输出目录复跑；已有输出拒绝覆盖。没有执行新的代码/机器可读格式模型任务、生产并发恢复或最终人工验收；未改 UI，未重跑界面测试。

结论限于这些输入和模型条件：已验证合理表达的放行与所列真实缺陷的拦截，尚不能据少量任务证明整体交付成功率提高。早期失败和夹具问题不从记录中删除。
